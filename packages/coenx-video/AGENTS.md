# coenx-video package guide

- This is the shared code-authored video engine for the general agent and Targeted Learning.
- Keep the composition model serializable and versioned. Interactive logic is a validated AST; never use `eval`, `Function`, or execute strings from a compiled project.
- Standard MP4 rendering and interactive playback share the same composition, timeline, scene geometry, and audio clip model, but have separate output pipelines.
- The standard renderer is deterministic and frame-addressable. Use bounded frame batches, a single active render by default, capped native threads, and an abort signal.
- Interactive playback must remain responsive on low-end devices: cap device pixel ratio and frame rate, defer media decoding, and pause when hidden.
- Keep Rust for repeated physics simulation and other measured hot loops. Keep TypeScript for authoring, validation, orchestration, and DOM/input behavior. A TypeScript fallback must preserve the same physics contract.
- Native sidecars communicate over newline-delimited JSON. Never log protocol output to stdout.
- Do not download media implicitly. Resolve local assets within the project root; remote URLs require an explicit user-supplied media workflow.
- Keep source files below 300 lines. Split schemas, timeline, runtime, renderers, physics, CLI, and adapters into separate modules.
- The world model (`src/interactive/engine.ts`, `src/interactive/expressions.ts`, `src/physics/live.ts`) powers interactive scenes: `hover`/`drag`/`collide` triggers, `run`/`gotoFrame`/`setNode`/`impulse` statements, arithmetic/`concat`/`clamp` expressions and a live 2D physics world stepped per frame. `setNode` color overrides restyle `fill` on solid-fill shapes and `color` on text. Overrides and hidden nodes snapshot per scene and restore on navigation.
- `CanvasVideoRenderer.draw()` draws in stage space scaled to the backing store (`canvas.width / stage.width`); never reset that transform to identity or non-stage-sized canvases clip everything beyond the top-left corner. `sizeCanvas()` owns the backing dimensions.
- The app's `CoenxInteractivePanel` mounts the player paused and exposes restart + play/pause in the panel header (handle kept in a Solid signal). Live physics only steps while playing.
- The world-showcase (`scripts/world-showcase-composition.ts`) is the reference world: ball arena (click impulse, hover, drag-throw, collide counters), molecules heat chamber (gravity-free gas, thermal impulses, hot/cold color overrides) and a grounded quiz. Pack with `bun scripts/pack-showcase.ts` into `exports/` and drive it in the session viewer; the headless proof is `test/world-demo.test.ts`.
- Run `bun test` and `bun run typecheck` in this package. Run native `cargo fmt --check`, `cargo test --offline`, and `cargo clippy --offline -- -D warnings` when changing Rust.
- After changing Rust or the physics hot path, re-measure: `bun scripts/bench-live-physics.ts` (in-process JS, the interactive player path) and `bun scripts/bench-native-physics.ts` (sidecar batch path, includes spawn + JSON round-trip). Both sidecars were built + verified 2026-11-27 (Rust 1.100.0): `coenx-video-native` 607 KB via `bun run build:native`, `divee-retrieval` 4 MB via `cargo build --release` in `packages/learning/native/retrieval`. The sidecar never runs in the interactive player — the browser cannot spawn it, and per-frame JSON round-trips would regress the hot path; native amortizes in the headless export batch where `simulate` + cairo `render_frame` share one process.

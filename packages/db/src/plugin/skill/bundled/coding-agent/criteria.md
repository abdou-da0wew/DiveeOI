# Coding Task Criteria

Use these checks to keep implementation aligned with the user's request.

## Scope

- Preserve explicit acceptance criteria and standing constraints.
- Separate required behavior from assumptions or potential follow-up work.
- Check project instructions and relevant durable memories before making architectural decisions.
- Keep modifications focused; explain optional improvements rather than silently expanding scope.

## Risk and approval boundaries

Pause for user input when a missing decision materially changes the solution, when an operation is destructive or externally visible, or when credentials, permissions, or dependency installation are required.

Do not ask for approval to continue routine implementation that the user has already requested.

## Verification

For each behavior change, identify at least one observable test or manual check. Distinguish passing checks from checks that were unavailable or not run.

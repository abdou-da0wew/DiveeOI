# Durable Coding Context

Use DiveeOI's existing memory and project-context facilities rather than creating a parallel `~/code/memory.md` file.

Capture only information likely to remain useful across sessions, such as:

- User-requested working preferences and corrections.
- Stable project architecture, conventions, and test procedures.
- Important decisions, constraints, and known limitations.

Keep project-specific facts scoped to that project. Do not store credentials, tokens, private personal data, transient task details, or assumptions presented as facts. Update an existing relevant memory instead of creating a duplicate. Follow the current memory policy when deciding whether an observation is durable enough to retain.

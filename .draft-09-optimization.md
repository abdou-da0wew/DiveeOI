# Draft 09 — Optimization System (files 38-44)

## Why intensive memory/speed work was needed
- Original server had 5-min stall on every prompt exit/compact: `memory.extractSessionMemory` was awaited inline inside `prompt.ts:1262/1290` loop exit. One slow LLM extraction blocked next turn's first token.
- GC was hardcoded interval, not profile-aware; heap/RSS unbounded; tool concurrency not capped by cores; SSE/WS queues unbounded; SQLite PRAGMA cache fixed 64MB; pty ticket cache fixed.
- No process-level profiler; no emergency backpressure.

## Adaptive Resource System (packages/db/src/adaptive)
- detect.ts (114 lines): cross-platform SystemResources {totalMemoryMB,availableMemoryMB,cpuCores,platform}. Linux: /proc/meminfo MemAvailable fallback MemFree; macOS: sysctl hw.memsize + vm_stat pages free+inactive*4096; Windows: os.freemem; fallback 4096/1024.
- profiles.ts (86): ResourceProfile comfortable/balanced/constrained/critical with thresholds {minFreeMB, minFreeRatio} (4096/0.5,1024/0.2,512/0.1,0/0). BASE_TARGETS rss500 heap300 gc30s tool4 LLM100 SSE500 WS500 pty2000 ttl60s cache600s sqlite64 etc. PROFILE_MULTIPLIERS scale: comfortable 700/400/60s/8/200/1000/1000 etc; critical 250/150/8s/1/25/100/100 etc. computeProfile checks freeMB+freeRatio. computeTargets caps rss=min(mult, total*0.12) heap=min(mult,total*0.07) concurrency=min(mult, cpuCores). interpolateTargets 0.3 factor smooth.
- service.ts (68): Ref<AdaptiveTargets|Profile|SystemResources|null>, detect initial, subscribers Set, updater Effect.forever sleep 90s detect freshProfile/freshTargets compare prev: if profile flip snap else interpolateTargets 0.3, set Refs notify subscribers, logInfo. forkScoped in layer. subscribe returns unregister.
- hooks.ts (34): useAdaptiveTargets(f), withAdaptiveConfig(makeConfig,useResource), makeAdaptiveLayer(makeLayer) unwrappable.

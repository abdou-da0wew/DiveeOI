# Draft 10 — Autonomous Agent (v2, implementation-grade)

Source: design discussion on running DiveeOI as a long-running autonomous agent on free/small
LLMs (Zen free models, ≤128k contexts). Core principle: **the agent is autonomous AND manual —
both, smart by default.** Manual is autonomous with a human in the loop; every autonomy mechanism
degrades gracefully to manual control.

v2 replaces the v1 sketch with implementation detail, researched design choices, per-tier
performance budgets, and a cross-platform matrix. Verified against the codebase 2026-09-21.

---

## 0. Operating constraints & hardware tiers

The agent must run flawlessly on BOTH ends of this spectrum:

| | Target low-end box | High-end box |
|---|---|---|
| CPU | Gen-2 i7 (4C/8T Sandy Bridge, ~3.4GHz, AVX, no AVX2) | 8+ modern cores |
| RAM | 8GB DDR3, shared with OS + browser | 32GB+ |
| Disk | 7200rpm HDD (~100 IOPS random, ~120MB/s seq) | NVMe SSD |
| GPU | 10-year-old, irrelevant | irrelevant |

**GPU policy: none.** All LLM work is remote (Zen gateway / any OpenAI-compatible provider). No
local inference is planned anywhere in this document; the bad GPU costs us nothing. If local
models are ever wanted they'd run CPU-only via a provider entry (out of scope).

The **adaptive system already exists** — `packages/db/src/adaptive/` (detect.ts reads real
MemAvailable per OS; profiles.ts has `constrained`/`balanced`/`comfortable` with rssTargetMB
350/500/700, maxToolConcurrency 2/4/8, sqliteCacheMB 16/64/128; service.ts re-detects every 90s
and broadcasts to subscribers). **Every new subsystem hooks `AdaptiveResourceService.subscribe`
and reads `getCurrentTargets()`** — we extend the target set, we don't build a second
profiler. Measured baseline: RSS 516MB all features on, 374MB off.

**Extended targets to add to `AdaptiveTargets`** (new fields, same profiles):

| Target | constrained | balanced | comfortable | Used by |
|---|---|---|---|---|
| maxConcurrentTasks | 1 | 2 | 4 | P4 task scheduler |
| heartbeatIntervalMs | 60_000 | 45_000 | 30_000 | P3/P4 |
| watchdogStallMs | 300_000 | 240_000 | 180_000 | P3 |
| ftsBatchRows | 500 | 2_000 | 5_000 | P1 indexing |
| anchorCacheTTLms | 120_000 | 300_000 | 600_000 | P1 |
| anchorCheckpointEveryToolCalls | 0 (compaction only) | 15 | 10 | P1/P8 |
| ftsOptimizeDebounceMs | 600_000 | 300_000 | 120_000 | P1 |

`detect.ts` gains one field: `storageHint: "hdd" | "ssd" | "unknown"` — Linux:
`/sys/block/<rootdev>/queue/rotational`; macOS: assume SSD; Windows: infer from
`Get-PhysicalDisk` when available, else unknown. HDD flips `ftsBatchRows` one tier down and
forces WAL checkpoint debouncing (§ P1).

## 0b. Cross-platform baseline fixes (P0 — required before anything new)

- **Windows paths**: `packages/db/src/global.ts` derives everything from `xdg-basedir`, which on
  win32 yields `C:\Users\<u>\.config\diveeoi` etc. (works, not idiomatic, ignores `%APPDATA%`).
  Fix in `global.ts` only: on `win32` use `process.env.APPDATA ?? xdgConfig` for config,
  `%LOCALAPPDATA%` for data/cache/state. Keep `os.homedir()` dot-folders on posix. Add a
  smoke test that boots with a fake win32 home layout.
- **Process control**: `kill_process` uses `taskkill /PID <pid> /T /F` on win32 (no signals);
  `restart.ts` already uses `process.exit` + detached spawn — verified win32-safe.
- **Signals**: never rely on SIGTERM/SIGUSR for in-server features (Windows has none cross-
  process); use Effect fiber interrupts + DB flags (the watchdog/task design already does).
- **fs.watch recursion** works on win32/macOS, is per-directory on Linux — `watch_file` uses the
  existing FSUtil watcher abstractions, not raw fs.watch.
- **Line endings / paths**: tools normalize `C:\\` and CRLF at input parsing (existing tools
  already do; new tools follow).

## 0c. Research findings that shaped this plan

1. **Bun SQLite ships FTS5 on all platforms** (enabled since bun 0.6.12; `bun:sqlite` is 3–6x
   faster than better-sqlite3) → FTS5 is our retrieval engine, no embeddings/vector DB (which
   would also violate the no-GPU/RSS budget). Probe still runs at P0 boot (§ P0).
2. **WAL + `synchronous=NORMAL` is correct for HDD** — no fsync per commit, sync at checkpoints;
   durability against app crash, vulnerable only to power loss (acceptable for agent scratch
   data; the message log already accepts this). Repo already sets it
   (`database.ts:30-33` with `busy_timeout=5000`, `cache_size=-sqliteCacheMB*1000`). We add
   batched transactions around FTS writes, nothing else changes.
3. **MemGPT/Letta memory hierarchy** (arXiv 2310.08560; letta.com) validates our split:
   in-context "core" memory that the agent self-edits, external searchable "recall" storage,
   unbounded "archival". Our anchor tree = core (self-editable via `anchor_edit`), originals =
   recall (`recall_context`), FTS5 = archival search (`search_memory`). Adopted from Letta:
   **the agent edits its own anchor between compactions**, not just at compaction time.
4. **AI SDK retry semantics**: `streamText` `maxRetries` handles transient errors, `onError`
   allows one extra recovery per step; for sustained 429 the community pattern is an explicit
   fallback chain across models (`ai-fallback` pattern). We implement rotation ourselves at the
   service layer (`retry.ts` extension) because (a) we already own that file, (b) we need
   circuit breakers + event emission the wrapper libs don't give.
5. **Loop detection**: practical agents guard with hashing — SHA-256 of tool + canonical args,
   interrupt at 3–4 identical consecutive calls; ambiguous tool feedback ("more results
   available") is the top loop trigger, so tool authors must make truncation explicit (our
   truncate.ts already reports truncation states — good).
6. **ssh2 on Bun**: pure-JS but leans on Node crypto internals; crashy reports are from 2023
   Bun, likely fine on 1.3.14, unproven → P0 boot probe + degrade path (§ P7).

## P0 — Foundations (no behavior change)

**Deliverables:** all new tables; Windows paths fix; adaptive target extension; two boot
probes.

**Drizzle migration** (one file, additive):

```sql
CREATE TABLE session_anchor (
  id TEXT PRIMARY KEY,               -- anc_…
  session_id TEXT NOT NULL,
  epoch INTEGER NOT NULL,            -- ties into session/context-epoch.ts
  root_ref TEXT NOT NULL,            -- "msg:<id>" of the original user objective
  tree_json TEXT NOT NULL,           -- validated anchor tree (sections → refs)
  token_estimate INTEGER,
  created_at INTEGER NOT NULL
);
CREATE INDEX idx_anchor_session ON session_anchor(session_id, epoch DESC);

CREATE TABLE session_anchor_ref (
  anchor_id TEXT NOT NULL,
  ref TEXT NOT NULL,                 -- "msg:<id>" | "part:<id>" | "tool:<call_id>"
  section TEXT NOT NULL,             -- objective|decisions|files|open_questions|status
  label TEXT NOT NULL,               -- short human/agent-readable line
  ordinal INTEGER NOT NULL
);
CREATE INDEX idx_anchor_ref ON session_anchor_ref(anchor_id);

CREATE VIRTUAL TABLE session_content_fts USING fts5(
  session_id UNINDEXED, ref UNINDEXED, text,
  tokenize = 'porter unicode61'
);

CREATE TABLE agent_task (
  id TEXT PRIMARY KEY,               -- task_…
  session_id TEXT UNIQUE NOT NULL,   -- a task IS a session
  parent_session_id TEXT,
  prompt TEXT NOT NULL,
  provider_id TEXT, model_id TEXT,
  status TEXT NOT NULL,              -- queued|running|paused|awaiting_permission|done|failed|cancelled|interrupted
  auto_run INTEGER NOT NULL DEFAULT 0,
  subagent_types TEXT,               -- JSON array allowlist
  event_hooks TEXT,                  -- JSON: [{trigger, action, payload}]
  last_heartbeat INTEGER,
  checkpoint_anchor_id TEXT,
  worktree TEXT,                     -- git worktree path for revert
  error TEXT,
  created_at INTEGER NOT NULL, updated_at INTEGER NOT NULL
);

CREATE TABLE agent_task_event (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  task_id TEXT NOT NULL, trigger TEXT NOT NULL, action TEXT NOT NULL,
  payload TEXT, status TEXT, result TEXT, fired_at INTEGER NOT NULL
);
```

FTS5 retention: cap per-session rows (default 50k; `constrained`: 20k) — oldest evicted by rowid;
`INSERT INTO session_content_fts(session_content_fts, rank) VALUES('optimize', ...)` runs on the
debounce timer, only while no other write txn is pending (HDD: also defer when
`storageHint === "hdd"` until idle).

**Boot probes** (in `features.ts`-adjacent `probes.ts`, results exported into
`GET /global/features`): (a) FTS5: `CREATE VIRTUAL TABLE temp.p USING fts5(x)` in a temp db —
if it throws, P1 tools degrade to LIKE search (still functional, slower); (b) ssh2:
`await import("ssh2")` — if it throws, P7 skips binding and reports `ssh.available: false`.

**Verify:** migration applies over existing DBs (35+ precedent); Colab typecheck + boot +
`PRAGMA integrity_check` green.

## P1 — Lossless context: linktree anchors

**Problem:** summary compaction is lossy; the agent forgets the objective and builds on faded
anchors. Everything else in this plan leans on this phase.

**Data flow:** compaction trigger logic stays (`overflow.ts` + `context-budget.ts` + epoch).
What changes is the output step in `session/compaction.ts`:

1. Collect the to-be-dropped message range with ids/parts (already available to the projector).
2. Ask the *small* model (existing `small` stream path) with a dedicated prompt
   (`session/prompt/anchor.txt`): input = messages **with ids**, output = strict JSON tree
   `{objective: {ref}, decisions: [{ref, label}], files: [{ref, label}], open_questions: [...],
   status: {ref, label}}`. Enforce: refs must come from the provided ids.
3. Validate every ref against the DB; invalid → dropped; if the tree loses all refs → fall back
   to current head+tail retention (degraded, safe).
4. Persist `session_anchor` + refs; index the dropped text into FTS (batched, tier-sized txns).
5. Active context for the next request = anchor tree (≤ ~1.5k tokens, prefix-stable position)
   + recent tail raw. Originals never deleted — refs stay valid forever.

**Self-editing:** `anchor_edit` tool (Letta core-memory pattern) — agent rewrites its own
sections between compactions; writes a new anchor row (immutable history, epoch++ on
compaction). `anchorCheckpointEveryToolCalls` gates a soft reminder to the agent to update
status sections (constrained tier: compaction-only).

**Tools** (registry, gated by `Features.flags.memory`):
- `recall_context(ref | anchor section | msg range)` → verbatim original parts. Cache: per-
  session LRU (TTL `anchorCacheTTLms`) of resolved part text to avoid re-reading rows on repeat
  recalls.
- `search_memory(query)` → FTS5 MATCH with BM25 rank, `LIMIT 8`, returns refs + snippet
  (`snippet()` fn) + `recall_context` usage hint. Porter stemming helps code-ish queries;
  if probe failed → `LIKE '%q%'` with the same shape.
- `anchor_edit(sections)` → per above.

**UI:** read-only anchor panel on the session view (fetch from new `GET /session/:id/anchor`);
shows the agent's working memory; user can expand refs (client fetches parts via existing
message endpoints).

**Performance:** anchor cache ≤ 200KB/session; FTS index ≈ 2–3x raw text (bounded by retention
cap); generation cost = one small-model call per compaction (same as today's summary call — no
regression); per-request context assembly unchanged in complexity (anchor replaces the summary
string).

**Cross-platform:** pure SQLite — nothing platform-specific.

**Verify (Colab):** scripted session with ≥2 compactions on a Zen free model; assert objective
text recoverable via `recall_context`, seeded string findable via `search_memory`, RSS within
+5% of pre-change baseline, FTS txn batching visible in trace logs.

## P2 — Auto-healing model fallback

**Where:** `packages/server/src/session/retry.ts` (exists, 201 lines) grows the schedule;
`llm.ts` call site passes the model chain. AI SDK `maxRetries` set to 0 — we own retries.

**Classification** of stream failures: `rate_limit` (429), `server` (5xx), `network`,
`timeout` (no first token in N s), `auth` (no rotation — surface immediately), `abort` (user —
never retried).

**Schedule** (per attempt step):
```
for model in [primary, ...fallbacks]:
    for attempt in 1..maxRetriesPerModel (default 3):
        wait = min(cap, base * 2^attempt) with full jitter   # base 1s, cap 30s
        if circuit(model) open → skip to next model
        try stream → success: reset circuit, return
        classify error → rate_limit/5xx/network/timeout → continue
    open circuit(model) for 5 min after the 3rd consecutive failure
# all models exhausted once:
if compactOnExhaustion and not yet compacted this cycle:
    run P1 anchor checkpoint (context shrink — many "timeouts" are oversized contexts)
    retry chain once from primary
pause run/task → emit session.degraded on the event bus (UI toast + task hook can fire)
```

**Fallback list:** `llm.fallbacks` config (explicit list of provider/model) else default =
same-provider models of the same tier from the provider registry. Zen note: free-model limits
may be per-account rather than per-model — rotation is harmless either way and backoff covers
the per-account case.

**Mid-stream failure:** a stream that already emitted tokens cannot resume; we re-issue the
whole step with the next model. Safety: partial assistant output is discarded unless it was
fully persisted as a part — the projector only persists complete parts, so no dirty state.
Idempotency: tool calls from a failed step were never executed (execution happens after stream
completes in the current pipeline).

**State:** circuit breakers live in an in-memory Map keyed `provider:model` (per process; a
restart resets them — acceptable). Every rotation emits `{type:"model_fallback", from, to,
reason}` on the existing event stream → UI shows a one-line notice.

**Cost:** zero added tokens; adds at most one small-model compaction per exhaustion cycle.

**Verify (Colab):** mock provider route returning 429 twice then success → assert retry-with-
backoff, event trail, session completes; 429 forever → assert rotation order, compaction
trigger, then `degraded` event and paused state.

## P3 — Watchdog + stuck detection

**Where:** new `packages/server/src/session/watchdog.ts`. One supervisor fiber per active run
(forked by the runner, scoped to the run), wakes on `heartbeatIntervalMs`.

**Signals** (all already observable in the session pipeline):
1. **No-progress stall** — no new persisted part AND no LLM event for `watchdogStallMs`.
2. **Repetition** — ring buffer (last 32 calls) of `sha256(toolName + canonicalJson(args))`
   (sorted keys, whitespace-normalized). Interrupt when: same hash ≥3 consecutive, or same
   hash ≥5 within last 20.
3. **Heartbeat** — doubles as P4's task liveness (same column, same fiber).

**On trip:** interrupt the run fiber → write `session.watchdog` event with the diagnosis →
restart the run from the last anchor checkpoint with an injected system-reminder part:
`"Watchdog: <tool> repeated N times / stalled Ms. Diagnose, change approach, or call
checkpoint."` Cap 3 auto-restarts per session without progress; then pause + degraded event.

**Tuning:** stall thresholds from adaptive targets (300s on constrained — HDD tool spawns are
slow; 180s comfortable). The ring buffer is ~4KB/session; hashing is µs — negligible.

**Verify (Colab):** fake tool that always returns identical output; assert interrupt at 3rd
call, restart with diagnosis, pause after 3 restarts, all events present.

## P4 — Agent tasks (persisted, restartable, self-managed)

**Decision (from v1, kept):** tasks are **Effect fibers via BackgroundJob + SQLite rows**, not
OS child processes — the session engine, tools, and permission model are in-process; OS
children would need IPC and a second permission surface. Reboot-survival = persistence +
resume.

**`AgentTask` service** (`packages/server/src/task/task.ts`, module shape per
`.zcode-quality.md`; new feature flag `tasks`):

```
create(input: {prompt, model?, autoRun?, subagentTypes?, hooks?, parentSessionID?}) → Task.Info
update(id, {prompt?, model?, subagentTypes?, hooks?}) → Info        # allowed while queued/paused
cancel(id) | pause(id) | resume(id) | stopLLM(id)                   # stopLLM = fiber interrupt, status paused, session kept
list(filter) → Info[] | output(id, {sinceLine?}) → tail             # tail from session parts
revert(id)                                                          # git worktree reset (below)
```

Internals: `create` makes a child session, optional git worktree branch (`worktree = task id`),
forks the runner fiber (same path a user-driven prompt takes → healing/watchdog inherit for
free), plus a heartbeat fiber writing `last_heartbeat` (also updated on every persisted part).
On settle: status update, hook dispatch, event log row.

**Boot resume** (in `main.ts`, after bind + `waitForParentExit` + health): scan
`status IN (running, queued) AND auto_run` → rows with stale heartbeat get `interrupted` then
resume fresh from `checkpoint_anchor_id` + replayed tail; fresh rows resume as-is. Non-auto or
paused rows stay inert, visible in UI. Resume is **after** healthy so a crash-looping task can
never block startup; scheduler respects `maxConcurrentTasks`, overflow queues.

**Event hooks** (stored JSON, dispatched on state transitions):
`trigger ∈ {on_complete, on_fail, on_timeout, on_output_match}` ×
`action ∈ {run_command, notify, webhook, create_task}`. `run_command` goes through the shell
tool path (permissions apply, output captured); `webhook` = fetch POST; `on_output_match`
regex is evaluated in the stream tap. Every dispatch writes `agent_task_event` (audit trail;
UI shows hook results).

**Permissions & autonomy:** task sessions run under `subagent-permissions.ts` derivation from
the parent agent. A pending approval sets `awaiting_permission` (UI badge); autonomous default
proceeds for auto-allowed tiers. `revert` = `git worktree` branch reset (or no-op when no
worktree was created).

**HTTPApi** (new group in `@diveeoi/api`, existing auth): `POST /api/v1/tasks` (create, returns
id immediately), `GET /api/v1/tasks`, `GET /api/v1/tasks/:id`, `DELETE /api/v1/tasks/:id`
(cancel), `GET /api/v1/tasks/:id/events` (SSE via existing event bridge). This endpoint is the
curl surface for P7. **UI:** Tasks panel = list + badges; detail view = the existing session
view (a task *is* a session — zero new chat UI).

**Verify (Colab):** create → kill -9 server mid-run → boot → task resumed from checkpoint and
completes; cancel/pause/resume semantics; `on_complete → notify` hook fires and is logged;
SSE stream delivers parts.

## P6 — Machine tools (tiered, cross-platform)

New modules under `packages/server/src/tool/` (each `<name>.ts` + `<name>.txt` description,
registry entry, permission default):

| Tool | Linux | macOS | Windows | Permission |
|---|---|---|---|---|
| `notify(title, body)` | `notify-send` (headless → no-op ok) | `osascript display notification` | PowerShell toast XML (slow spawn ~1s — fire-and-forget) | auto |
| `get_system_info` | `os` module + Adaptive detect (already cross-OS) | same | same | auto |

| `http_request(url, method, headers, body)` | fetch, host allowlist check | same | same | auto for allowlisted, **approval** otherwise |

| `clipboard(read/write)` | `xclip`/`wl-copy`+`wl-paste` | `pbcopy`/`pbpaste` | `clip.exe` / PowerShell `Get-Clipboard` | read auto, write **approval** |

| `watch_file(path, timeout)` | FSUtil watcher | same | same | auto |

Implementation rules: every external-binary call (a) resolves once via an availability probe
cached per process (HDD: first spawn is a seek — cache the "missing" verdict too), (b) has a

(`{available:false, reason}` instead of tool-crash on missing binaries — headless Linux boxes
return graceful no-ops). Approval-gated tools reuse the existing question/permission UI path;
in unattended tasks they block with `awaiting_permission` (P4) rather than failing.

**Verify:** per-tool smoke on Colab (Linux path); Windows/macOS paths covered by unit tests
that stub `spawn` (no real Windows in CI) + one manual pass documented in docs/.

## P7 — Access surfaces: SSH REPL, curl, messaging

**SSH** (`packages/server/src/ssh/` module — in-server, needs the layer graph; NOT a separate
package):
- `ssh2` server; host key: `crypto.generateKeyPairSync("ed25519")` PEM persisted at
  `Global.Path.data/ssh_host_key` on first boot (no `ssh-keygen` dependency — Windows-safe).
- Auth: same password as HTTP auth; non-password methods rejected. Binds `127.0.0.1:2222` by
  default (`ssh.host`/`ssh.port`/`ssh.enabled` config + `ssh` feature flag + settings-UI toggle
  via the shipped Features tab pattern).
- REPL commands: `run <prompt>`, `tasks`, `status <id>`, `logs <id> [follow]`, `cancel <id>`,
  `models` — direct in-process service calls (no HTTP hop), output with ANSI via a tiny
  renderer over the existing event stream.
- **Degrade path:** P0 probe failed → don't bind, `ssh.available:false` in `/global/features`,
  REPL surface remains usable via curl (below).

**curl:** P4's TaskApi is the surface; ship `script/divee.sh` that prints the exact one-liner
(base URL + basic-auth from env) for `run`/`tasks`/`logs -f`. Works from any device with curl;
SSH-tunnel or reverse-proxy exposure stays the operator's call.

**Discord/Telegram bots:** new thin packages (`packages/discord-bot`, `packages/telegram-bot`)
that import **only `@diveeoi/sdk`** — slash-command/message in → `POST /tasks` → stream events
→ edit the channel message. New flags `integrations` (default off until configured) — these
are the only genuinely new runtime deps (`discord.js`/`grammy`) and they're isolated in their
own packages so the server RSS is untouched.

**Verify (Colab):** SSH round-trip on loopback (auth ok/rejected, run → streamed output,
tasks list); curl create→SSE→done; bots: mock-gateway unit tests only.

## P8 — System prompt rewrite (smart by default)

`session/prompt.ts` + agent prompt txts:
- **Objective anchoring:** the anchor root ref is resolved verbatim into every post-compaction
  request — never a summary of a summary.
- **Memory instructions:** "The anchor is an index, not the memory. Before concluding you
  don't know something, `search_memory`; when a ref looks relevant, `recall_context`."
- **Checkpointing:** `anchor_edit` status updates every `anchorCheckpointEveryToolCalls`
  (tier-gated) and at milestones; restarts resume from it.
- **Self-correction:** watchdog restarts inject the diagnosis; instruct
  diagnose → change-approach → escalate (pause + notify) on repeat failure.
- **Model economy:** cheap models for mechanical subagents; strong ones for reasoning.
- **Manual mode unchanged:** the human's message is just another anchor root; all autonomy
  machinery is additive fibers/tools, never a mode switch.

## Risks & mitigations (decided)

- **FTS5 absent** (unlikely): LIKE-search fallback, same tool shapes — no tool-contract break.
- **ssh2 on Bun**: P0 probe + degrade; SSH is an enhancement, curl is the guaranteed surface.
- **Anchor under-referencing** (LLM emits few/invalid refs): validation drops + fallback to
  head+tail (never worse than today); `anchor_edit` lets the agent repair its own anchor.
- **Free-model per-account limits** make rotation useless: backoff + compaction + pause cover
  it; rotation still helps when limits are per-model (common on Zen).
- **HDD write storms**: batched FTS txns, debounced optimize, tier-scaled heartbeats —
  no per-event fsync anywhere (WAL+NORMAL already set).
- **Restart-resume correctness** is the riskiest piece (P4): only started after P1 lands; the
  anchor checkpoint + session replay is what makes resume tractable.

## Open items (decide at build time, low-stakes)

- Whether `AgentTask` wraps `BackgroundJob` or runs a sibling registry (BackgroundJob.make
  already owns settle semantics — likely wrap).
- Whether `on_output_match` evaluates on raw stream text or parts only (parts are the persisted
  truth; raw allows mid-part matches — probably raw with parts as fallback).

# Draft 10 — Autonomous Agent (autonomous AND manual, smart by default)

Source: design discussion on running DiveeOI as a long-running autonomous agent on free/small
LLMs (Zen free models, ≤128k contexts). Core principle agreed with the user: **the agent can be
autonomous AND manual — it is both — and smart by default.** Manual is autonomous with a human in
the loop; every autonomy mechanism degrades gracefully to manual control, and smart behavior is
the default, not an opt-in.

This version is anchored to the actual codebase (verified 2026-09-21). Everything builds on the
existing Effect-TS layer graph, the feature-flag system (`packages/server/src/features.ts`), the
memory subsystem, `BackgroundJob`, and Drizzle/SQLite. No new runtime dependencies except where
noted (`ssh2`, optional messaging bots).

Gap analysis vs. the goal "runs for hours unattended": the missing pieces are (1) lossless
context, (2) self-healing across model failures, (3) stuck detection, (4) persisted/restartable
tasks, (5) machine tools, (6) out-of-band access surfaces, (7) autonomy-shaped prompts.

## Resolved design decisions (answers to the open questions)

**D1 — Anchor storage: dedicated tables in the same SQLite DB.** New Drizzle tables
`session_anchor` (one row per anchor checkpoint: session_id, epoch, root_ref, json tree, created)
and `session_anchor_ref` (anchor_id, ref kind: `msg`/`part`/`tool`, message_id, part_id, label,
section). FTS5 virtual table `session_content_fts` indexing compacted message/part text, rebuilt
incrementally at anchor time. Rationale: the anchor must be server-renderable (UI shows the
agent's working memory) and independently queryable; stuffing it into a message string would
repeat the lossy-summary mistake. The original messages/parts are **never deleted** — compaction
only changes what goes into the LLM request (existing `MessageV2` projector), so refs stay valid.

**D2 — Tasks are Effect fibers, not OS child processes.** The session engine, tools, and
permissions all live in the server process; an OS child process would need IPC to reach them and
would fork the permission model. A "task process" = `BackgroundJob` fiber + SQLite row. What
makes it survive reboots is persistence + resume, not process isolation:

- New table `agent_task`: id, session_id, parent_session_id, prompt, model (provider/modelID),
  status (`queued|running|paused|done|failed|cancelled`), auto_run (bool), subagent_types (json),
  event_hooks (json), last_heartbeat, checkpoint (anchor ref), error, timestamps.
- `BackgroundJob` gains `persist`/`resume` (or a sibling `AgentTask` service wrapping it —
  implementation detail at build time; `BackgroundJob.make` already owns the fiber registry and
  settle semantics).
- On boot: `SELECT status IN ('running','queued') AND auto_run` → re-fork each onto its stored
  session; `paused`/non-auto tasks stay inert and visible in the UI.
- OS child processes are still used *inside* the task (bash tool) — unchanged.

**D3 — SSH auth: reuse the server password; host key auto-generated at first boot** under
`Global.Path.data/ssh_host_key`, bind `127.0.0.1` by default (config: `ssh.host`, `ssh.port`,
`ssh.enabled` + feature flag `ssh`). Same password as HTTP auth, so one credential controls all
surfaces. Public exposure stays the operator's reverse-proxy decision.

**D4 — Linktree checkpoint replaces the summary, incrementally.** Compaction keeps its
trigger/overflow logic (`overflow.ts`, `context-budget.ts`) untouched. What changes is the
*output*: instead of one prose summary, the LLM is prompted (existing compaction prompt pattern)
to emit a structured anchor tree (sections: objective / decisions / files / open questions /
status), each leaf a `ref:msg_id[:part_id]`. Validation: refs must resolve to real rows, else the
entry is dropped and the raw tail kept — an anchor can under-reference, never fabricate. The
active context becomes: anchor tree (compact) + last N messages raw. Everything else is recalled.

## Phases

### Phase 0 — Schema foundation (no behavior change)

- Drizzle migration adding: `session_anchor`, `session_anchor_ref`, `session_content_fts`,
  `agent_task`, `task_event_log` (trigger, action, payload, fired_at, result), `heartbeat`
  (job_id, beat_at) — or heartbeat as a column on `agent_task` + reuse for watchdog on sessions.
- New `packages/server/src/anchor/` module: `Anchor.Service` (write/read/query anchors, resolve
  refs → original parts), self-reexport per module shape rules. Registered in the layer graph,
  gated by `Features.flags.memory`.
- Verify: migration applies on existing DBs (35+ migrations precedent), typecheck on Colab.

### Phase 1 — Lossless context: linktree anchors

- Rewrite `compaction.ts`'s summarize step to emit the anchor tree (D4). Keep epoch machinery
  (`context-epoch.ts`) — an anchor belongs to an epoch.
- Tools (registered via tool registry, gated by `memory` flag):
  - `recall_context(ref | session range | anchor section)` → returns original message/part
    content verbatim.
  - `search_memory(query)` → FTS5 top-k refs (+ `recall_context` idiom in the tool description).
- Prompt injection: active context = anchor tree + recent tail; system prompt says the anchor is
  an *index*, originals are never gone, recall before claiming ignorance (full wording in P8).
- UI: render anchor tree on the session (read-only panel) so the user sees the agent's working
  memory.
- Verify on Colab: run a session ≥ 2 compactions on a Zen free model; assert (a) original
  objective text is recoverable via `recall_context`, (b) FTS search returns the right ref for
  seeded content, (c) RSS delta vs old compaction within +5%.

### Phase 2 — Auto-healing model fallback

- Extend `retry.ts` into a healing schedule: per-model retries (default 3, exponential backoff)
  → rotate through `fallbacks` (default: same-tier free models from the same provider list)
  → on exhaustion, run a compaction checkpoint (P1) and restart the chain from primary
  → still failing: pause the run/task, emit a `session.degraded` event on the existing event bus.
- Config: `llm.fallbacks` per model, or a global `healing` block (schema in `ConfigV1.Info`).
- Works for both interactive sessions and P4 tasks; UI shows "switched to X after limit on Y"
  from the emitted events (small toast/log entry, no new page).
- Verify on Colab: scripted 429 injection (mock provider route) → assert rotation order and that
  the session completes; assert event stream carries the rotation events.

### Phase 3 — Watchdog + stuck detection

- `packages/server/src/session/watchdog.ts`: one fiber per active run; wakes every 30s; rules:
  no LLM event/tool call for N seconds (default 180, config), same tool+args hash M times in a
  row (default 4), or heartbeat age > 2× interval → interrupt fiber, write anchor checkpoint,
  restart the run with a self-correction prefix (what looped, what failed).
- Emits `session.watchdog` events; never auto-kills more than K times (default 3) per task —
  then pauses and notifies (degraded event → all surfaces).
- Doubles as the task supervisor in P4 via the heartbeat column.
- Verify: simulated infinite loop (tool that always fails) on Colab → assert interrupt + restart
  + eventual pause with event trail.

### Phase 4 — Agent task management (persisted, restartable)

- `AgentTask` service (D2) + tools: `create_task`, `update_task` (prompt/model/subagent allowlist),
  `cancel_task`, `stop_task_llm` / `resume_task_llm` (pause fiber, keep task),
  `revert_task_changes` (git worktree/branch per task — the task session runs on its own
  worktree like plan mode, revert = branch reset), `list_tasks`, `get_task_output` (tail).
- Event hooks: `on_complete|on_fail|on_timeout|on_output_match` → action
  `run_command|notify|webhook|task` — executed through the existing shell tool path so
  permissions apply; hooks log to `task_event_log`.
- Boot resume (D2): auto_run tasks re-fork after `waitForParentExit`/bind — after the server is
  healthy, not during boot, so a crash-looping task can't block startup.
- Human overlay in the web UI: tasks list with status/model/prompt, pause/resume/cancel, live
  tail (reuses existing session view — a task *is* a session).
- Verify: create task → restart server mid-run → task resumes from checkpoint; cancel/stop/resume
  semantics; hook fires `notify-send` on complete.

### Phase 5 — Subagent + model choice extension

- Agent picks per-subagent model from an allowed list (`agents.<name>.model` + task-level
  `subagent_types` allowlist). Defaults keep current behavior (same model as parent).
- New built-in guidance in prompts (P8) about cheap-vs-strong model choice for subagents.
- Surface allowed types/models to the agent through the existing `task` tool schema (enum from
  config, so the LLM can't invent types).
- Verify: task with `subagent_types: ["researcher"]` rejects `coder` dispatch with a tool error
  the LLM can recover from.

### Phase 6 — Machine tools (tiered permissions)

- New tools in `packages/server/src/tool/`: `notify`, `get_system_info`, `list_processes`,
  `kill_process`, `http_request`, `screenshot`, `clipboard`, `glob_search` (fast path over
  existing glob), `watch_file`.
- Permission tiers via the existing permission system: info/read tools auto-allowed;
  `kill_process`, clipboard write, `http_request` to non-allowlisted hosts require approval
  (fires the question/permission UI path that already exists; in autonomous mode with no human
  attached, they queue as pending permission requests and the task waits).
- Verify: each tool has a Colab smoke (notify on headless = no-op log), permission denial path
  returns a tool error, not a crash.

### Phase 7 — Access surfaces: SSH REPL + curl + messaging

- SSH server (`ssh2`) per D3: minimal REPL — commands `run <prompt>`, `tasks`, `status <id>`,
  `logs <id> [follow]`, `cancel <id>`, `models`. Talks to the services in-process (no HTTP
  hop). New package `packages/ssh-server` or a `packages/server/src/ssh/` module (prefer the
  latter — it needs the layer graph; a separate package would only re-import the server).
- curl: `POST /api/v1/tasks` (P4's HTTPApi group) + `GET .../stream` (SSE over the existing event
  bridge). Ship `script/divee.sh` — a zero-dependency curl one-liner generator (prints the exact
  command for the current server URL + token).
- Discord/Telegram: thin bot packages importing `@diveeoi/sdk` only; messages become task
  prompts, streamed output edits the channel message. Feature flag `integrations`; off by
  default until configured.
- Verify: SSH REPL round-trip on Colab (loopback), curl start→stream→done.

### Phase 8 — System prompt rewrite (smart by default)

- `packages/server/src/session/prompt.ts` + agent prompt txts:
  - **Objective anchoring**: original task restated from the anchor root at every checkpoint
    (never a summary of a summary — the root ref is the literal original message).
  - **Memory instructions**: when to `recall_context`/`search_memory` (before concluding
    ignorance; after any ref in the anchor is unclear).
  - **Progress checkpointing**: call `checkpoint(summary)` (thin wrapper → anchor update) every
    ~10 tool calls or at milestones; restarts resume from it.
  - **Self-correction loop**: watchdog restarts include the loop diagnosis; instruct
    diagnose→switch-approach→notify escalation.
  - **Model economy**: pick cheap subagent models for mechanical work.
- Manual mode unchanged: the human's message is just another anchor root; all autonomy machinery
  is additive.

## Sequencing & flags

Order: **P0 → P1 → P2 → P3 → P4 → P5 → P6 → P7 → P8.** P1 first (lossless context is the
foundation everything else leans on); P2+P3 before P4 so tasks inherit healing and supervision;
P7 last because every surface is just a client of P4's API.

Feature flags (extend `features.ts` KNOWN, default on, UI toggles auto-wire through the shipped
settings tab + restart): `tasks` (P4/P5), `ssh` (P7), `integrations` (P7 bots). `memory` gates
P1. Every phase stays usable in manual mode.

## Risks

- **FTS5 availability**: Bun's bundled SQLite supports FTS5; verify in P0 on Colab before
  building on it (`SELECT fts5(?1)` probe at migration time).
- **Anchor drift**: LLM-written refs may rot if parts are ever purged — mitigate: parts are
  never deleted (D1/D4), and anchor validation drops unresolvable refs at read time.
- **Runaway cost/limits on free models**: healing rotation + watchdog pause caps are the
  guardrails; every escalation ends in a *pause + notify*, never silent infinite retry.
- **Restart-resume correctness**: P4 is the riskiest phase; the checkpoint (anchor) + session
  replay machinery from P1 is what makes it tractable. Do not start P4 before P1 lands.

## Verification policy (all phases)

Typecheck + build + boot smoke on the Colab session (`divee_typecheck_build`), never locally;
each phase adds a scripted probe like the feature-flag verification (boot → exercise → assert →
restore). Phase gates are cumulative: a phase is done when its probe passes on a fresh clone of
the pushed branch.
